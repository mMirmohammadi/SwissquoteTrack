## What the build gap does and does not block

**Recommendation:** replace the plan's unconditional source/build prerequisite with an explicit bounded acceptance route for P0. Full reproducible source/build equivalence remains necessary before making that stronger provenance claim, but is not itself necessary to replace an already disproven ±1 predicate with exact, independently checked observations on a previously pinned third-party deployment.

The safety improvement is narrow: every admitted result must satisfy exact balance, principal and accrued-index equations, while existing signed call shape, token amount/recipient, permissions, debt, code pins and fresh observed hash remain strict. If a model input is unavailable or a getter disagrees, refuse rather than fall back to a tolerance. A differing deployment implementation cannot be silently substituted.

This route still trusts the pinned third-party contracts and the RPC simulation. Matching getters and two nodes cannot prove the bytecode has no hidden paths or that the getters are honest. The model can reject behavior outside its subset; it cannot turn an unaudited market into a trusted one. Do not describe this deployment as an official Compound market or promise state will remain identical until mining. If product acceptance requires audited semantics or source identity rather than the existing third-party pin trust, the build/equivalence gap remains a release blocker under that stronger requirement.

## Prioritized blockers before correctness/live acceptance

### P0-A — Pin the new execution dependency and configuration

Keep every existing proxy, implementation, admin, token, router, quoter and pool check. Main implementation remains `0xe3e0106227181958abfba960c13d0fe52c733265`, hash `0x210f4eb2374e25850607bdb9f4f41f183c1cc881e932a0e4f304279ef3f6e4f9`. Add a canonical same-base-block `extensionDelegate()` address check and runtime hash check using the saved address/hash above **before trusting extension totals/scales**. Inspect the extension's relied-on dispatch/getter paths for further proxy/delegate dependencies; pin those or reject unsupported indirection. Main pin alone does not close an unreviewed delegation edge.

At each fresh simulation, check baseToken/baseScale, index/factor scales and the actual immutable supply-rate constants against the approved configuration. Check the public rate getter at a known utilization against the independent integer formula. Configuration reads and all code/storage reads must use the same explicit base block, never independent `latest`. Check chain identity and bind the simulated parent to that base header; reject a detected reorg or incoherent block evidence. Freshness must not reuse an old successful pin check for a later relay.

### P0-B — Exact typed evidence and arithmetic; no amount envelope

Retain the eight original probes. Add named Compound-only typed probes for `userBasic`, `totalsBasic`, `getUtilization`, plus whichever configuration/rate/scales probes are actually adopted. The plan's minimum is 11 before + 3 actions + 11 after = 25 supply calls, or 23 withdrawal calls; its extended option is 31/29. Base-block configuration reads are additional reads, not secretly counted simulation probes. Define one deterministic action-specific probe plan shared by construction and parsing; appended tuple probes must **not** enter the existing `checks.slice(4)` allowance loop. Preserve swap counts and semantics.

Require exact canonical static ABI lengths: five words for `(int104,uint64,uint64,uint16,uint8)` userBasic and eight words for `(uint64,uint64,uint64,uint64,uint104,uint104,uint40,uint8)` totalsBasic. Validate signed sign extension, every unsigned width, addresses, tuple re-encoding and no trailing words. Scalars cannot parse tuples or signed principal. Require complete successful results, canonical block/time quantities, simulation number base+1, time in uint40 domain and time >= stored last accrual. A malformed response must refuse; it must not be misclassified as an RPC outage and bypassed through fallback.

Compute utilization from stored totals/indices, not post-action totals. Independently derive the rate from checked constants; compute J from stored supply index and simulation time. With S=index scale, P=starting principal, B=floor(P*J/S), signed action A=(+a supply or -a withdrawal), require nonnegative P and B+A, then Q=floor((B+A)*S/J), C=floor(Q*J/S). Require exact observed before balance B, after principal Q, after balance C, after supply index J and stored action accrual time. Preserve source-compatible zero-elapsed behavior. Validate intermediate overflow, narrowing and signed arithmetic/reverts; unrestricted BigInt is not Solidity execution.

Check total supply principal after = before + (Q-P), total borrow principal unchanged and no debt before/after. Validate relevant aggregate-index behavior with an explicit borrow model if post-utilization agreement is enforced; do not pretend the post utilization can be derived using the old borrow index. Non-modeled tuple fields must be typed and have a documented allowed-change rule, rather than accidentally freezing tracking accrual or allowing collateral flags to change silently. Fail closed on unsupported/non-monotone principal transitions rather than generalizing this supply-only subset without evidence.

### P0-C — Existing positions and withdrawals must not disappear

The fix must preserve positive-principal supply and withdrawal. Before/after views share J: interest already belongs in B, so it is not a free extra delta allowance. Admit partial withdrawal with exact modeled residual loss and full withdrawal of B to Q=0; reject a>B, negative starting/ending principal, hidden negative principal whose displayed debt is zero, repayment and borrow crossing. Empty fresh supply remains supported; empty withdrawal rejects. Disabling withdrawals would be a scope change requiring explicit user approval, not a harmless implementation shortcut.

Acceptance needs positive-P supply/partial withdrawal/full withdrawal vectors, elapsed accrual and zero elapsed, tiny supply with Q=P/no mint, plus index-scale boundary and integer-width/revert cases. The recorded zero-P sample alone cannot establish these paths. Source-compatible event/accounting expectations must be reviewed for the admitted principal-transition subset, not inferred from the single mint sample.

### P0-D — Make event evidence real, not an address allowlist

[Current action log handling](</home/dev/Hackaton/SwissquoteTrack/.worktrees/v3/swissquote-wallet/packages/protocol/src/simulate.ts#L122-L141>) accepts empty arrays, ignores Compound log semantics and does not require a withdrawal Transfer amount equal to a. Replace that for Compound with exact per-call event grammar/cardinality/order and canonical indexed/data layouts. Supply must show approvals a/revoke0 in the correct calls, USDC wallet→Compound amount a and Supply(wallet,wallet,a). Withdrawal must show no approvals, USDC Compound→wallet amount a and Withdraw(wallet,wallet,a). Reject missing/duplicate/extra events even from allowed contracts; reject collateral, borrow, manager or unrelated EURC events. Require observational getters to produce no unexpected mutation logs as well.

Mint/burn amount is `floor(abs(Q-P)*J/S)` when the corresponding principal difference is positive, not generally abs(C-B). Supply mint is zero→wallet; withdrawal burn is wallet→zero. Do not require an event when Q=P, or rewrite balances to fit events. Review actual pinned/source-candidate order for withdrawal; the zero-P supply replay establishes only its own USDC Transfer → Supply → mint order. Event validation does not replace exact wallet balances or principal/index checks.

Keep exact USDC spend/receive, unchanged EURC and unrelated allowances, selected supply allowance zero before/after, no debt, canonical recipient/amount, one withdrawal or exact approve/action/revoke sequence, zero values and CALL operations. Do not silently strengthen every unrelated allowance to zero: the current rule is unchanged for unrelated permissions; selected permissions must be zero. Preserve that policy unless separately approved.
